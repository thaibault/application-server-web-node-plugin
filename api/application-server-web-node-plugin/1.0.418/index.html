application-server-web-node-plugin 1.0.418

Project status

Use case

This web-node plugin starts an HTTP server and hands every incoming request to the plugin hook chain. It is the shared foundation for web-node plugins and applications which answer HTTP requests.

Features included:

  • Plain HTTP/1 server or encrypted HTTP/2 server as soon as a certificate is configured.
  • Hooks to handle requests and HTTP/2 streams in any other plugin.
  • Graceful shutdown which closes all open sockets and streams.

Content

Installation

Install the plugin next to web-node. web-node discovers every installed package whose name ends with "-web-node-plugin" automatically:

yarn add web-node application-server-web-node-plugin

Configuration

Override the defaults in the "webNode" section of your application's "package.json":

{
    "webNode": {
        "applicationServer": {
            "hostName": "0.0.0.0",
            "port": 443,
            "nodeServerOptions": {
                "allowHTTP1": true,
                "cert": "<certificate in PEM format>",
                "key": "<private key in PEM format>"
            }
        }
    }
}
  • "hostName": Interface to listen on. Defaults to "127.0.0.1".
  • "port": Port to listen on. Defaults to "8080".
  • "nodeServerOptions": Options passed to Node's "http2.createSecureServer". As soon as "cert" and "key" are given an encrypted HTTP/2 server is started, otherwise a plain HTTP/1 server.

Handling requests

Implement the hook "applicationServerRequest" in your application or plugin. Each request runs through all plugins implementing it. The response is finished automatically afterwards:

import type {
    PluginHandler, ServicePromisesState, RequestData
} from 'application-server-web-node-plugin/type'

export const plugin: PluginHandler = {
    applicationServerRequest: async (
        {data: {request, response}}: ServicePromisesState<RequestData>
    ): Promise<void> => {
        if (request.url === '/health')
            response.write('ok')
    }
}

Further hooks and services:

  • "applicationServerStream": Called for every HTTP/2 stream, only available on encrypted servers.
  • "services.applicationServer": Holds the Node server "instance" and its open "sockets" and "streams".
